# Colday 2026

Музыкальный сайт-визитка с админ-панелью. Сервер на Go, фронтенд — нативная SPA (vanilla JS).

## Архитектура

```
colday2026/
├── main.go                    # Точка входа, конфиг, роутинг
├── internal/
│   ├── models/models.go       # Модель Release
│   ├── store/store.go         # Хранилище: чтение/запись JSON-файла
│   ├── auth/auth.go           # Аутентификация: HMAC-SHA256 сессионные куки
│   └── handlers/              # HTTP обработчики
│       ├── handlers.go        #   общие хелперы (writeJSON, readJSON)
│       ├── releases.go        #   CRUD релизов
│       ├── auth_handlers.go   #   login / logout / me
│       ├── upload.go          #   загрузка обложек
│       └── middleware.go      #   RequireAuth
├── static/
│   ├── colday.html            #   публичная страница
│   ├── goatadmin.html         #   админ-панель
│   └── favicon.svg
├── data/
│   └── data.json              #   файл БД (создаётся автоматически)
├── Dockerfile
└── docker-compose.yml
```

Чёткое разделение слоёв:

| Слой      | Пакет      | Ответственность                               |
|-----------|------------|-----------------------------------------------|
| **API**   | `handlers` | HTTP-роутинг, парсинг запросов, JSON-ответы   |
| **Auth**  | `auth`     | Подпись/верификация HMAC-кук, проверка пароля |
| **Store** | `store`    | CRUD, персистентность, потокобезопасность     |
| **Model** | `models`   | Структуры данных                              |

## Хранилище

Вместо базы данных используется `data/data.json` (настраивается через `COLDAY_DATA_FILE`). Все CRUD-операции
потокобезопасны (`sync.RWMutex`), запись атомарная (write-to-tmp + rename).
Перед переименованием временный файл синхронизируется с диском. Изменения публикуются в памяти
только после успешной записи: при ошибке API возвращает HTTP 500, прежние данные сохраняются.

Формат файла:

```json
{
  "releases": [
    {
      "id": 1,
      "title": "Название",
      "release_type": "album",
      "cover": "/static/uploads/abc.jpg",
      "bandlink": "https://band.link/...",
      "upc": "1234567890",
      "original_date": "2024-03-15",
      "counter_songs": 10,
      "song_duration": "00:35:00",
      "featured": true
    }
  ],
  "next_id": 2
}
```

При старте файл создаётся автоматически, если его нет.

## API

Все эндпоинты возвращают `Content-Type: application/json`.

### Публичные

| Метод  | Путь                 | Описание                              |
|--------|----------------------|---------------------------------------|
| `GET`  | `/api/releases`      | Список всех релизов (featured первый) |
| `GET`  | `/api/releases/{id}` | Один релиз по ID                      |
| `POST` | `/api/login`         | Вход (тело: `{"password":"..."}`)     |
| `POST` | `/api/logout`        | Выход                                 |
| `GET`  | `/api/me`            | Статус аутентификации                 |

### Требуют аутентификации

| Метод    | Путь                 | Описание                                   |
|----------|----------------------|--------------------------------------------|
| `POST`   | `/api/releases`      | Создать релиз                              |
| `PUT`    | `/api/releases/{id}` | Обновить релиз                             |
| `DELETE` | `/api/releases/{id}` | Удалить релиз                              |
| `POST`   | `/api/upload-cover`  | Загрузить обложку (multipart, поле `file`) |

### Статические файлы

- `/` — публичная страница (`colday.html`)
- `/admin` — админ-панель (`goatadmin.html`)
- `/static/*` — прочие статические файлы

## Запуск

### Локально (Go)

```bash
# Установить переменные окружения
export COLDAY_ADMIN_PASSWORD=secret

# Запустить
go run .
```

### Docker

```bash
# Создать .env из шаблона и задать COLDAY_ADMIN_PASSWORD
cp .env.example .env

# Запустить
docker compose up -d --build
```

Сайт: `http://localhost:8080/`, админка: `http://localhost:8080/admin`.

Приложение собирается статически (`CGO_ENABLED=0`) в отдельном Go-этапе. Финальный образ —
[`gcr.io/distroless/static-debian13:nonroot`](https://github.com/GoogleContainerTools/distroless):
без shell и пакетного менеджера, пользователь `65532:65532`. Корневая файловая система
контейнера в Compose доступна только для чтения; `/tmp` — небольшой tmpfs.

Существующие пути хранения сохранены:

| Compose | Данные на хосте | Обложки на хосте |
|---------|----------------|-----------------|
| `docker-compose.yml` | `./data/data.json` | `./static/uploads/` |
| `deploy/docker-compose.yml` | `./data/data.json` | `./uploads/` |

Пути относительны соответствующему Compose-файлу. Одноразовый сервис `storage-init` на BusyBox
перед запуском приложения назначает владельцем этих двух каталогов и их содержимого UID/GID
`65532:65532`. Это позволяет перейти с прежнего Alpine-контейнера и запускать новую установку
без ручного `chown`. Он завершается после подготовки; приложение работает без root.
При изменении `COLDAY_DATA_FILE` или `COLDAY_UPLOADS_DIR` нужно также изменить соответствующие
монтирования приложения и `storage-init`.

Для сохранения входа в админку после пересоздания контейнера один раз добавьте в `.env`
`COLDAY_SESSION_KEY` (например, результат `openssl rand -hex 32`). Для HTTPS задайте
`COLDAY_COOKIE_SECURE=1`; локально по HTTP используйте `0`.

Для обновления опубликованного образа на сервере:

```bash
cd deploy
docker compose pull
docker compose up -d
```

В админке сохранение и переключение релизов блокируются на время загрузки обложки.
Максимальный размер файла — 8 МБ; превышение возвращает HTTP 413 без сохранения обрезанного файла.

## Конфигурация

Все настройки через переменные окружения (или `.env` файл):

| Переменная              | По умолчанию         | Описание                              |
|-------------------------|----------------------|---------------------------------------|
| `COLDAY_ADDR`           | `:8080`              | Адрес сервера                         |
| `COLDAY_ADMIN_PASSWORD` | **обязательно**      | Пароль админа                         |
| `COLDAY_DATA_FILE`      | `data/data.json`     | Путь к файлу хранилища                |
| `COLDAY_SESSION_KEY`    | эфемерный (32 байта) | HMAC-ключ для кук (hex, ≥64 символов) |
| `COLDAY_STATIC_DIR`     | `static`             | Директория со статикой                |
| `COLDAY_UPLOADS_DIR`    | `static/uploads`     | Куда сохранять обложки                |
| `COLDAY_COOKIE_SECURE`  | `""`                 | `"1"` — Secure флаг на куке (HTTPS)   |

## Тесты

```bash
go test -race ./...
# Проверки админки без дополнительных npm-зависимостей (Node.js 22+)
node --test tests/admin.test.cjs
```

- CRUD релизов (включая featured-логику, граничные случаи)
- Аутентификация (вход/выход, неверный пароль, просроченная кука)
- Загрузка обложек (с файлом, без файла, неизвестное расширение)
- Персистентность данных
- Ошибки диска: HTTP 500 без изменения данных в памяти и без расходования ID
- Параллельная запись и восстановление устаревшего счётчика ID
- Админка: ожидание загрузки обложки, защита от повторного сохранения, сохранение черновика при ошибке
  и повторном входе, редактирование релизов с типом в нижнем регистре
- Вход, загрузка обложки вне каталога статики, редактирование и удаление через реальный HTTP-роутер
  с повторным открытием хранилища
